## Image accounting

- himon-rom-c000: CODE 10,664, DATA 1,174; dense component 12,288 bytes including 450 bytes of FF padding.
- asm-v1-flash-8000: CODE 14,542, DATA 693; dense component 16,384 bytes including 1,149 bytes of FF padding.
- APMAN: BODY 3,031, envelope overhead 46, package 3,077, carrier 4,096, erased carrier tail 1,019 bytes.
- APMAN contains 555 stored worker bytes; they are already included in BODY.
- APMAN raw linker `_END_CODE=$EBD7` is not its CPU end. Use `APMAN_IMAGE_END=$7BD7`, confirmed by S19 and package BODY.

ASM UDATA is `$5000-$6D6D` (7,534 allocated bytes), not emitted ROM.
APMAN overlays `$7000-$7BD6`; its 41-byte gap ends at `$7C00`.
Neither allocation proves runtime high-water or maximum stack use. Those
lifetime/stack questions belong to the next audit; no new RAM is assigned.

Bank-3 component allocation remains four ASM sectors plus three HIMON sectors.
The STR8-N top sector is separate. APMAN consumes one external 4K carrier
sector when installed; package size and occupied flash sectors are distinct.
